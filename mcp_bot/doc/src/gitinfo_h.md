# gitinfo.h

## File Purpose
This header file contains automatically generated Git repository information for the GZDoom codebase. It provides version identification details derived from the Git repository, which are used throughout the engine for version reporting, debugging, and compatibility checks. The file is not meant to be edited manually, as indicated by the comment at the top, but is instead generated by the "updaterevision" tool whenever the codebase is built from a Git repository.

## Key Components

### Git Version Information

- **`GIT_DESCRIPTION`**: A string containing a human-readable description of the current Git version, including the base version tag, number of commits since that tag, and a shortened Git hash. The format typically follows the pattern `[version]-[commits]-g[hash]-[modifiers]`, such as "g4.15pre-247-gd3f965e86-m".

- **`GIT_HASH`**: The full 40-character hexadecimal Git commit hash that identifies the exact commit from which the build was created. This provides a precise reference to the source code state.

- **`GIT_TIME`**: The timestamp of the Git commit, including date, time, and timezone offset. This indicates when the commit was made, which can be useful for tracking the age of a build.

## Technical Details

### Generation Process

The file is automatically generated by the "updaterevision" tool, which is part of the GZDoom build system. This tool:
1. Queries the Git repository for information about the current commit
2. Formats this information into C preprocessor macros
3. Writes the macros to the gitinfo.h file

### Usage in the Codebase

These macros are used in various parts of the GZDoom codebase to:
- Display version information in the game's title screen and console
- Include in crash reports to help with debugging
- Log in configuration files to track which version created them
- Provide version information for compatibility checks

### Format of GIT_DESCRIPTION

The `GIT_DESCRIPTION` macro follows Git's describe format:
- "g4.15pre" indicates the base version tag (with "g" prefix for GZDoom)
- "247" indicates this build is 247 commits ahead of that tag
- "gd3f965e86" is the abbreviated Git hash (with "g" prefix as per Git convention)
- "m" indicates there are local modifications not committed to Git

## Connections with Other Modules

- Connected to the version reporting system, which displays version information to users
- Used by the crash reporting system to include version details in crash reports
- Referenced by the configuration system to track which version created configuration files
- May be used by networking code for version compatibility checks

## Notable Features

- Automatically generated, ensuring accuracy without manual intervention
- Includes both human-readable description and precise commit hash
- Provides timestamp information for chronological tracking
- Indicates when local modifications exist that aren't in the repository
- Serves as a single source of truth for Git version information throughout the codebase
